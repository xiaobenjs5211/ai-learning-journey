4Day 4 · 拆开参数，搞懂到底在调什么

约 1 小时。这天不写新功能，只做实验。仓库里 explore_params.py 已经写好了 5 个实验，直接跑就能看出差别。

Day 4运行 explore_params.py，逐个看现象约 1 h
python explore_params.py
实验你要看懂的东西
1. system 的作用同一个问题，加了 system 就变成「教授口吻、限 60 字」。system 是给模型立规矩的地方
2. assistant 角色把模型的回复以 assistant 身份塞回列表，它就能记住上一轮。多轮对话的全部秘密就在这两行 append
3. temperature0.01 时两次回答几乎一样；1.5 时两次完全不同。低值做代码和数据处理，高值做文案和头脑风暴
4. max_tokens设 30 会话说一半就断 —— 它是输出上限，不是目标长度
5. token 用量看看每次调用到底消耗多少。上下文越长 → token 越多 → 越贵越慢，这是第 3 周「上下文管理」的动机
今天唯一要背下来的东西messages 是一个角色列表，三种角色：system（定规矩）、user（你说的）、assistant（模型说的）。后面所有的 Agent、RAG、工具调用，全都建在这一个结构上。今天理解透了，第 7 周会轻松很多。
做完实验 2 的对比后，把 history.append(...) 两行注释掉再跑一次，亲眼看它「失忆」

8卡住了怎么办 · 报错速查表

这周你大概率会碰到下面某一条。先来这里对一下，别急着去搜。

'python' 不是内部或外部命令 / python: command not found
终端是旧会话没刷新环境变量。→ 关掉终端重开，或直接用 py hello_ai.py。还不行就检查是否在 VS Code 里选错了终端。
ModuleNotFoundError: No module named 'zhipuai'
虚拟环境没激活。→ 命令行开头必须有 (.venv)。没有就先跑 .venv\Scripts\activate。
ModuleNotFoundError: No module named 'sniffio'
zhipuai SDK 的依赖声明漏了。→ pip install sniffio。这条我已经帮你处理并写进 requirements.txt 了。
AuthenticationError: invalid api key, please check your api key
两种可能：① Key 复制时带了空格或换行；② 账号还没做实名认证。→ 重新复制一遍，光标扫过首尾按 Delete 确认干净。
无法加载文件 ...activate.ps1，因为在此系统上禁止运行脚本
PowerShell 的执行策略限制。→ 最简单：终端换成 Command Prompt。或执行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned。
调用失败：HTTPSConnectionPool ... Read timed out / Connection error
网络抖动或代理问题。→ 重跑一次；换手机热点试试。这类错误在写 try/except 之后会显示成「调用失败：...」而不是一长串红字，这就是异常处理的价值。
fatal: unable to auto-detect email address / Please tell me who you are
没配 user.email。→ 跑 Day 6 第一步那两条 git config 命令。
git push 被拒：rejected ... Updates were rejected because the remote contains work
建仓库时勾了 README，远程有本地没有的提交。→ git pull --rebase origin main 然后再 git push -u origin main。
error: remote origin already exists
之前关联过远程地址。→ git remote set-url origin 你的新地址 覆盖掉。
git status 里居然看得见 .env
.gitignore 没生效。→ 确认文件名是 .gitignore（前面有个点），且放在项目根目录、和 .env 同一层。改名/新建后重新 git status。
搜报错的正确姿势别把整段报错粘进搜索框。只搜关键词：zhipuai ModuleNotFoundError sniffio、git push rejected remote contains work。另外优先看官方文档，其次是 Stack Overflow 和 GitHub Issues，别一上来就翻二手教程 —— 这也是你原计划里写的话。
